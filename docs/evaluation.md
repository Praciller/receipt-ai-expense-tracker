# Synthetic Extraction Evaluation

`npm run test:evaluation` runs offline against [`../fixtures/evaluation-cases.json`](../fixtures/evaluation-cases.json). The twelve fictional cases cover Thai and English receipt fields, full and short Buddhist Era dates, service charge, VAT plus discount, source spans, missing required fields, invalid dates/currency, low confidence, and item or grand-total mismatches. Fixture IDs must be unique; duplicate IDs stop the evaluation so one case cannot overwrite another in reports.

The generated files are [`../reports/extraction/summary.md`](../reports/extraction/summary.md) and [`../reports/extraction/metrics.json`](../reports/extraction/metrics.json). Every rate includes its numerator and eligible denominator. Field exact match counts four expected comparisons per schema-valid case (merchant, normalized date, currency, category); numeric tolerance counts only numeric monetary fields present in the fixture; completeness counts ten normalized review fields per valid case. Warning, reconciliation, and item-mismatch metrics include only cases with an expected result for that check. A metric with no eligible cases is `0/0 (0%)`, not a perfect score.

The UI displays source text spans returned by a parser and warns when none are available. Source evidence coverage measures span presence only; it does not establish that a span is authentic or correctly recognized. The deterministic mock does no image reading and returns authored fixture data. External-provider mode can invoke an image-capable provider, but this evaluation does not measure that provider or OCR quality.

These metrics verify deterministic normalization, validation, reconciliation, warning behavior, and output completeness on a small synthetic fixture set. They are not estimates of field-level OCR accuracy, model quality, tax correctness, or production reliability. Next steps are a consented Thai/English benchmark with independently annotated values and source locations, document-type stratification, field-level precision/recall, and monetary-error distributions. Keep private receipts, provider responses, and credentials out of the repository.
